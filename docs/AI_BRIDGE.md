# Мост Codex ↔ Claude через GitHub

Репозиторий: `ypftctnbrb-maker/CRYPTOSCOPE`.
Codex пишет код и тесты в отдельных ветках `codex/*`; Claude независимо читает diff.
Общая точка обмена — PR, его точный head SHA и комментарии проверки.
Чаты и память двух сервисов не синхронизируются.

## Однократное включение

1. Приложение Claude для GitHub должно иметь доступ к CRYPTOSCOPE.
2. Добавить **один** секрет в Settings → Secrets and variables → Actions:
   - `CLAUDE_CODE_OAUTH_TOKEN`, полученный через `claude setup-token`, для подписки Claude;
   - либо `ANTHROPIC_API_KEY` из Claude Console для API с отдельным биллингом.
   Если заданы оба секрета, workflow выбирает OAuth.
   Значения нельзя присылать в чат, коммитить или добавлять в комментарии.
3. Проверить и слить PR установки моста. До слияния автоматический запуск не включён.
4. На открытом PR написать `@claude review` отдельным комментарием.
   Альтернатива: Actions → Claude bridge → Run workflow → номер PR.
5. Проверить успешный запуск, комментарий «Проверка Claude» с актуальным SHA
   и получение комментария обратной автоматизацией Codex.
   До этого полный проход моста не считается проверенным.

## Запуск и ограничения

- Открытие/обновление готового PR из `codex/*` запускает Claude автоматически.
- Для другой внутренней ветки доступен комментарий `@claude review` от пользователя с write-доступом.
- Fork PR не обслуживаются; автоматические проверки draft PR пропускаются.
- Боты не могут вызывать Claude комментариями. Повторная проверка уже обработанного SHA пропускается.
- Запуск ограничен 15 минутами и восемью ходами Claude. Большие diff требуют отдельной ручной проверки.
- Используется доверенный workflow; исходники PR не запускаются и не checkout-ятся.
- Claude читает предоставленные GitHub patches; отсутствие замечаний не доказывает отсутствие ошибок.
- Если PR изменился во время анализа, результат отбрасывается. Отчёт относится только к прочитанному SHA.
- Тесты остаются в существующих workflows. AI-проверка не заменяет CI и не выполняет merge/deploy.

## Обратный канал

Событийная автоматизация ChatGPT слушает PR-комментарии и проверки этого репозитория, включая ботов.
Её фактический статус нужно проверять отдельно: файлы этого PR не создают подписку ChatGPT.
Она принимает отчёты с маркером `cryptoscope-bridge:claude:<SHA>`, проверяет автора/источник и актуальность SHA.
Свой ответ помечает `cryptoscope-bridge:codex:<ID комментария Claude>` и повторно его не обрабатывает.
Ответы Codex не содержат команды запуска Claude. Новая проверка нужна только после нового коммита.
Не более двух автоматических циклов исправлений на один PR; дальше — сообщение владельцу.
Конфликты, отсутствие воспроизведения, среды или тестов не скрываются. Автоматическое слияние запрещено.

## Проверка и диагностика

Локальная проверка логики: `node --test tests/claude-bridge.test.cjs`.
Если секрета нет, workflow падает на `Check Claude authentication` с понятным сообщением.
Если секрет невалиден или подписка исчерпана, результат нужно проверять в шаге `Review with Claude`.
Секреты не читаются и не проверяются локальными тестами.
Отключение: отключить workflow `Claude bridge` и отдельную событийную автоматизацию ChatGPT.

Официальная документация: https://code.claude.com/docs/en/github-actions
