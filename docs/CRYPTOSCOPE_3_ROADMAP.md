# CRYPTOSCOPE 3.0: привлечение аудитории и аналитические инструменты

Статус: утверждено к разработке, НЕ означает, что функции уже работают. Интерфейс только на русском языке.

## Обязательные разделы
1. **Карта ликвидаций и сквизов**: зоны вероятных ликвидаций с источником, методикой расчёта и предупреждением, если это оценка, а не биржевые данные. Нельзя выдавать оценочную тепловую карту за реальные ордера.
2. **Радар крупных держателей**: отслеживание публичных адресов и крупных переводов, притоков/оттоков на известные биржевые адреса; указывать сеть, транзакцию, время и статус атрибуции адреса. Нельзя трактовать каждый перевод как покупку или продажу.
3. **Календарь разлоков**: дата, количество, USD-оценка, процент циркулирующего предложения, тип получателя, первоисточник и время обновления.
4. **Радар аномалий**: изменения цены, объёма, OI, funding и волатильности за несколько интервалов; сравнение с исторической базой, источник и время обновления. Никаких гарантированных сигналов роста.
5. **Криптокалендарь**: ФРС, CPI, ETF, листинги, делистинги, голосования, апгрейды сетей; дата, часовой пояс, источник, степень подтверждения.
6. **Сравнение двух монет**: капитализация, FDV, циркулирующая и максимальная эмиссия, объём, ликвидность, цена, динамика, OI/funding при наличии, разработчики и разлоки при наличии.
7. **Telegram-бот**: подписки на монеты и типы событий, пороги, защита от спама, ссылки на соответствующие страницы CRYPTOSCOPE, отписка и удаление подписки.
8. **CRYPTOSCOPE Radar**: публичные карточки монет с зафиксированными аномалиями, временем расчёта, объяснением критериев и историей результатов. Не представлять результат как финансовую рекомендацию.

## Продуктовые требования
- Сохранить существующие функции BTC LIVE, рынок, графики, CVD, OI, funding и каталог перспективных монет; исправлять регрессии.
- Основная группа монет: капитализация от $200 млн. Отдельная группа: $20–200 млн.
- Не показывать вымышленные значения. При недоступности API выводить «Нет данных» и причину.
- Все страницы и метаданные на русском; URL для отдельных монет, событий, сравнения и радара.
- Для SEO: индексируемые страницы с серверным рендерингом или статической генерацией, sitemap.xml, canonical, уникальные title/description, robots.txt, корректные 404, структурированные данные там, где применимо.
- Для аналитики трафика: измерение переходов из поиска, Telegram, повторных посещений, CTR, скорости страниц; соблюдение приватности.
- Для источников: журнал API, лимитов, лицензий, стоимости и задержки. Для платных данных не имитировать доступность.
- Безопасность: ключи API и токен Telegram только на сервере, rate limiting, валидация входных данных, журнал ошибок, минимизация персональных данных.

## Архитектура
Текущий GitHub Pages SPA оставить работоспособным до запуска новой версии. Развивать v3 как приложение с отдельными маршрутами, серверным API, кешем и хранилищем исторических рядов. Выбор хостинга, БД и провайдеров данных сделать после проверки бюджета, лимитов и лицензий. Никаких секретов в браузерном JavaScript.

## Очередность реализации
- **Этап 0: аудит и тесты**. Зафиксировать состояние работающего сайта, сборку, smoke-тесты, ошибки загрузки API, доступность и скорость.
- **Этап 1: фундамент v3**. Маршруты монет, SEO, серверный слой и единая модель данных.
- **Этап 2: быстрый органический трафик**. Сравнение монет, криптокалендарь, календарь разлоков.
- **Этап 3: ежедневная полезность**. Радар аномалий, CRYPTOSCOPE Radar и исторические результаты.
- **Этап 4: сложные данные**. Радар китов и карта ликвидаций после проверки достоверных источников.
- **Этап 5: удержание**. Telegram-бот, подписки, оповещения, измерение возвратов.
- **Этап 6: публичный запуск**. Мониторинг, нагрузочные тесты, проверка корректности сигналов и SEO.

## Критерии готовности каждого раздела
1. Рабочий интерфейс, проверенный на телефоне и десктопе.
2. Реальные данные, проверяемые источники и время обновления.
3. Обработка ошибок, пустых ответов и лимитов API.
4. Автоматические тесты и проверка после деплоя.
5. Отдельное подтверждение доступности публичной страницы.
